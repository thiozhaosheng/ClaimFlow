# ClaimFlow

An expense claim portal for Singapore SMEs. An employee submits a receipt, the
system reads it and checks it against the company's IRAS and GST rules, an
approving officer reviews what is left, and finance pays it out. Three roles,
three services, one Postgres database.

## Layout

- `frontend/` — React single-page app built with Vite. The only part a user opens.
- `backend/auth-gateway/` — reverse proxy in front of the API. It signs people in,
  rate-limits, and forwards everything else.
- `backend/api/` — Express and Prisma: claims, workflow, audit log, the policy
  engine, and the Azure OCR and blob storage calls.
- `docs/` — GST/IRAS, PDPA and retention notes, and the testing evidence.

## Running it

You need Node 20 and a PostgreSQL database.

1. Copy `backend/api/.env.example` to `.env` and fill in `DATABASE_URL` and
   `JWT_SECRET`. The Azure keys are optional — without them the receipt scan
   returns nothing and every field is typed by hand. It is never faked.
2. Copy `backend/auth-gateway/.env.example` to `.env`. Its `JWT_SECRET` must
   match the API's, or tokens minted by one will not validate against the other.
3. Run `npm install` in `frontend`, `backend/api` and `backend/auth-gateway`.

Then, from the repository root:

```bash
npm run dev
```

That starts the API on port 3000, the gateway on 4000 and the web app on 5173.
The gateway is the only service the browser talks to.

To load the demo dataset, run `npm run prisma:seed` in `backend/api`. It clears
the tables first, so point it at a database you own.

## Tests

```bash
npm run test:unit         # Jest, backend and frontend
npm run test:e2e          # Playwright
npm run test:integration  # needs DATABASE_URL_TEST; skips itself without one
npm run test:perf         # k6
```

The integration tier skips itself unless `DATABASE_URL_TEST` points at a throwaway
database, since its fixtures truncate tables. The performance run needs k6
installed and the API up. Measured counts per tier are in
`docs/testing-evidence/pyramid.md`, which is generated by `npm run test:evidence`
rather than written by hand.

GitHub Actions runs the unit, integration and end-to-end tiers on every push to
`main` and `infra/azure-deployment`.
